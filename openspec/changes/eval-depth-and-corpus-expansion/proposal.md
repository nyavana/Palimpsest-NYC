## Why

Palimpsest NYC V1 has shipped (commit `e1bc76d` and follow-ups): a single-tool-becomes-two-tool agent (`search_places` + `plan_walk`) with a locked five-field citation contract, a two-tier LLM router, a ~1k-place corpus over a Morningside-Heights + UWS bounding box, a server-side OSM walk planner, an SSE frontend with `flyTo`, BYOK credentials, and a food-discovery side flow. The existing evaluation artifacts (`docs/eval/v1-eval-report.md`, `docs/eval/v1-router-comparison.md`) cover qualitative review of 5 walks and a cost comparison across 10 — too small for statistical claims and missing any non-agentic baseline.

The EECS E6895 final report needs numbers that (a) compare Palimpsest against traditional LLM techniques and (b) quantify the contribution of each Palimpsest component. This change adds three orthogonal capability blocks plus a corpus expansion so the report can carry a headline result ("Palimpsest produces X% higher citation correctness than vanilla LLM, Y% higher than naive RAG") and an ablation curve showing what each component contributes. The locked V1 contract — turn cap of 7, JSON terminal turn, five-field citation contract, one corrective retry — does not change.

## What Changes

- **ADD** Manhattan-wide corpus expansion: widen `SCOPE_BBOX` from MH+UWS to all of Manhattan, bump `SCOPE_VERSION`, re-run OSM + Wikipedia ingestors, optionally re-extract the OSRM PBF for the new bbox.
- **ADD** a `RETRIEVAL_MODE` env flag selecting one of three retrieval pipelines inside `search_places`: `dense` (current, refactored), `hybrid` (dense + pg_trgm sparse, merged with Reciprocal Rank Fusion), and `hybrid_reranked` (hybrid → `BAAI/bge-reranker-base` cross-encoder).
- **ADD** `app/retrieval/{dense,sparse,fusion,hybrid,reranked,factory}.py` modules. `DenseRetriever` is extracted from the inline retriever; the rest are new. A factory function dispatches on `RETRIEVAL_MODE`.
- **ADD** `app/embeddings/reranker.py` — `Reranker` singleton, conditionally constructed in `main.py` lifespan when `RETRIEVAL_MODE == hybrid_reranked` to avoid model-load cost in other modes.
- **ADD** `/internal/retrieve` and `/internal/documents/by_ids` routes — one-shot retrieval and document-lookup endpoints used by the naive-RAG baseline and the grader-side body-excerpt enrichment.
- **ADD** above-the-API eval harness under `docs/eval/scripts/`: `run_eval_v2.py` orchestrator, three baselines (`vanilla_llm`, `naive_rag`, `palimpsest` SSE consumer), an LLM-judge grader with pinned `judge.yaml`, an `aggregate.py` that computes per-system means, 95% CIs, Cohen's κ, and per-region / per-source / Pareto breakdowns.
- **ADD** a pre-registered 100-question bench at `docs/eval/questions/manhattan-100/` (single-place, multi-place, geographic, per-neighborhood, out-of-scope) with `categories.yaml` mapping each to category + region + expected source types. The commit is tagged so the report can cite "question bank @ commit ABCDEF".
- **ADD** a host-side venv at `docs/eval/.venv` driven by `docs/eval/requirements.txt` plus `make eval-setup` / `eval-deps` / `eval-shell` targets. Eval scripts run from the host against `http://localhost:8000` — they are deliberately NOT importable from inside the API container so the runtime image stays slim.
- **ADD** `RETRIEVAL_MODE` and `RERANKER_ENABLED` passthrough in `docker-compose.yml` so the same container produces all three Palimpsest ablation rows via env swap + restart.
- **MODIFY** `app/agent/tools/search_places.py`: replace the inline retriever with `retrieval.factory.build_retriever()`; tool-result shape stays byte-identical across modes (enforced by `test_retrieval_factory.py` and a shape-contract assertion in the existing `test_agent_search_places.py`).
- **MODIFY** `app/config.py`, `.env.example`, `apps/api/app/main.py` lifespan, and `Makefile` to support the above.
- **DEFER** multi-hop / query-decomposition agent changes, LLM-as-judge replacement of the inline citation verifier, live-web / Google Places baselines, additional source types beyond Wikipedia + OSM, and v2 VPS deploy.

## Capabilities

### New Capabilities

- `corpus-expansion`: widens `SCOPE_BBOX` from MH+UWS to all of Manhattan, bumps `SCOPE_VERSION` to `v2-manhattan`, requires auto-ingest to populate the wider corpus on `make nuke && make up`, and pins a retrieval-latency budget (`/internal/retrieve` p95 ≤ 2s at `RETRIEVAL_MODE=dense`) for the widened corpus. Trigram indexes are preserved from V1; OSRM resize is explicitly deferrable.
- `retrieval-pipelines`: pluggable retrieval pipelines (dense, hybrid dense+sparse with RRF, hybrid + cross-encoder rerank) selected at process start by `RETRIEVAL_MODE`, with an invariant that all retrievers share a uniform `.search(...)` signature returning the existing `SearchPlaceHit` shape and that the `search_places` tool-result shape is identical across modes. Also covers the `/internal/retrieve` and `/internal/documents/by_ids` endpoints that expose retrieval as a one-shot HTTP surface for the naive-RAG baseline and grader-side body-excerpt enrichment.
- `eval-harness`: above-the-API evaluation pipeline (orchestrator, three baselines, LLM-judge grader, aggregator) that runs a pre-registered 100-question Manhattan bench against multiple systems and emits the report's headline ablation table plus per-region, per-source, and accuracy-vs-latency Pareto figures, with Cohen's κ between hand- and LLM-judge grades on the 20-question calibration subset.

### Modified Capabilities

_None at the `openspec/specs/` level._ The locked V1 agent-tools behavior (five-field citation contract, turn cap, JSON terminal turn, one-retry verifier) is unchanged. The `search_places` internal retrieval pipeline now branches on `RETRIEVAL_MODE`, but its tool-result shape is required to be identical across all three modes — this constraint is owned by the new `retrieval-pipelines` capability spec (which now includes the shape-equivalence requirement as a tested invariant) rather than as a delta against `agent-tools`, since no main `openspec/specs/agent-tools/` directory exists yet (the initial-palimpsest-scaffold change has not been archived).

## Impact

- **Filesystem (created)**: `apps/api/app/retrieval/{__init__,dense,sparse,fusion,hybrid,reranked,factory}.py`, `apps/api/app/embeddings/reranker.py`, `apps/api/app/routes/internal_retrieve.py`, `apps/api/app/db/migrations/0003_widen_scope_indexes.sql`, `docs/eval/scripts/{run_eval_v2,sse_client,document_client,synthesize_questions,aggregate}.py`, `docs/eval/scripts/baselines/{vanilla_llm,naive_rag,palimpsest}.py`, `docs/eval/scripts/graders/{llm_judge,rubric}.py`, `docs/eval/scripts/{systems,judge}.yaml`, `docs/eval/requirements.txt`, `docs/eval/questions/manhattan-100/*`, `docs/eval/grades/calibration.csv`, `docs/eval/results/ablation_table.md`, plus matching `apps/api/tests/test_retrieval_*` and `docs/eval/scripts/tests/test_*` files.
- **Filesystem (modified)**: `apps/api/app/ingest/scope.py` (widened bbox + version bump), `apps/api/app/agent/tools/search_places.py` (use factory), `apps/api/app/config.py` (new settings), `apps/api/app/main.py` (conditional reranker singleton in lifespan + `/internal/retrieve` mount), `.env.example`, `apps/api/tests/test_agent_search_places.py` (shape-contract assertion), `docker-compose.yml` (env passthrough), `Makefile` (eval-setup targets), `.gitignore` (eval venv).
- **Runtime dependencies**: a new sentence-transformers cross-encoder (`BAAI/bge-reranker-base`, loaded conditionally from `hf-cache`), a new pip-installed `pg_trgm` SQL dependency (existing in postgres image; just needs the migration), and host-side eval deps (httpx, PyYAML, matplotlib, redis, pytest, pytest-asyncio) pinned in `docs/eval/requirements.txt`. None of the eval deps land in the API container image.
- **Database**: a new optional migration to verify spatial + trigram indexes survive the corpus widening. `make nuke && make up` is required to re-ingest at the Manhattan bbox; expected scale ~3–5k places + ~1.5–2k Wikipedia documents (verify against actual cardinality per risk R1 in the design).
- **OSRM**: `infra/osrm/extract.osm.pbf` may need to be re-extracted at the wider bbox; this is deferrable (per risk R8) since the eval headline metrics (CCR / HR / FA / NQ) do not depend on walk geometry.
- **Locked V1 contract**: untouched. The five-field citation contract, turn cap, JSON terminal turn, one corrective retry, and SSE event names are all preserved. The shape-contract assertion in `test_agent_search_places.py` is the tripwire.
- **Cost cap**: an LLM-judge full run on 500 rows (5 systems × 100 questions) at `anthropic/claude-opus-4-7` temperature 0 is bounded at ~$10 by the grading script; baselines and Palimpsest runs at `moonshotai/kimi-k2.6-20260420` add a similar bound.
